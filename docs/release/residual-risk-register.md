### Disposition vocabulary (normalised)

A row carries an explicit **`DISPOSITION:`** only when a named increment has
reached a final judgement on it. The allowed values are exactly:

| Disposition | Meaning |
| --- | --- |
| `RESOLVED (<increment>)` | The risk is closed by proven work in that increment. The row states what was proven and by which mechanism. Any part that is NOT closed is split into its own row rather than left implied. |
| `DEFERRED_TO_<INCREMENT>_WITH_EXPLICIT_REASON` | Deliberately not closed. The row must state the reason and must not overstate what is wired today. |
| `ACCEPTED_FOR_CLOSED_BETA` | Knowingly accepted for the closed beta, with the release implication stated explicitly. |

A row with **no** `DISPOSITION:` tag is simply **OPEN** — that is the default for
every row in the table below, as the opening paragraph states, and it is not a
weaker form of any value above. Rows inherited from earlier increments carry no
tag and remain open on their existing mitigation, owner and target date.
